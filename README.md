# leftjoin / rightjoin for C# LINQ query syntax

A patched Roslyn compiler that adds `leftjoin` and `rightjoin` query clauses
([csharplang discussion #8892](https://github.com/dotnet/csharplang/discussions/8892)),
plus an end-to-end test project that is compiled by the patched compiler.

```csharp
from s in students
leftjoin d in departments on s.DepartmentId equals d.Id
select (s.Name, Department: d?.Name);   // Enumerable.LeftJoin(...)
```

## Setup on a new machine

```bash
git clone --recurse-submodules https://github.com/jasekiw/csharp-leftjoin.git csharp
cd csharp
./scripts/e2e.sh
```

If you cloned without `--recurse-submodules`, run `git submodule update --init` first. The submodule is pinned to
a commit on `feature/leftjoin-rightjoin-query` in [jasekiw/roslyn](https://github.com/jasekiw/roslyn); run
`git -C roslyn switch feature/leftjoin-rightjoin-query` before making new Roslyn commits.

Requirements: Linux or macOS, the .NET 10 SDK (`e2e/global.json`), git, and roughly 16 GB of RAM for the Roslyn build.
Roslyn's own build installs the preview SDK it needs into `roslyn/.dotnet`.

## Layout

| Path | Purpose |
|---|---|
| `roslyn/` | Submodule with the compiler change (one commit on top of upstream `main`) |
| `scripts/build-compiler.sh` | Builds and packs Roslyn, copies the packages to `local-feed/`, writes `e2e/PatchedCompiler.props` |
| `scripts/e2e.sh` | Builds the compiler, compiles and runs the e2e tests with it, and checks that the stock compiler rejects the syntax |
| `e2e/` | xunit tests that use the new syntax; compiled with the patched `csc` from the local package |

`local-feed/`, `e2e/PatchedCompiler.props`, and `e2e/.nuget-packages/` are generated by the scripts and not committed.

Useful commands:

```bash
SKIP_COMPILER_BUILD=1 ./scripts/e2e.sh     # reuse the last compiler build

cd roslyn
./.dotnet/dotnet test src/Compilers/CSharp/Test/Semantic/Microsoft.CodeAnalysis.CSharp.Semantic.UnitTests.csproj \
  -c Release -f net10.0 --filter 'FullyQualifiedName~LeftRightJoinQueryTests'
./.dotnet/dotnet test src/Compilers/CSharp/Test/Syntax/Microsoft.CodeAnalysis.CSharp.Syntax.UnitTests.csproj \
  -c Release -f net10.0 --filter 'FullyQualifiedName~LeftRightJoinParsingTests'
```

## Design decisions

- **Single-word keywords.** `leftjoin`/`rightjoin` rather than the proposal's `left join`, because `left join` can
  already be valid C# (`x is T left` followed by `join`). The keywords are contextual, so variables named
  `leftjoin` keep working. Requires `LangVersion` preview.
- **`into` is not allowed** on `leftjoin`/`rightjoin` (error CS9404); use `join ... into` for group joins.
- **Nullability is scoped.** Only queries that contain `leftjoin`/`rightjoin` get real nullability: the
  `leftjoin` inner variable and the `rightjoin` outer variables are maybe-null, including in later clauses.
  All other queries are analyzed exactly as before.
- **`rightjoin` after several range variables** (`from s ... from n ... rightjoin d ...`): .NET passes `null` for
  the combined outer element when an inner element has no match. The compiler reads each outer range variable
  through a null check, so they become `null`/`default` instead of throwing. The proposed spec translation has
  this gap; worth raising upstream.

## Known limitations

- A null check in one clause does not carry to later clauses (each clause is a separate lambda), the same as
  with method syntax.
- After a `rightjoin` with several earlier range variables, `s == null ? x : s.Name` still warns; `s?.Name` works.
- In the full Roslyn Syntax test run, three deep-nesting tests (`TooDeepObjectInitializer*`) can fail depending on
  test order and stack depth; they pass when run alone, with or without this change.
